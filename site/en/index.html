01 / 14OPEN SOURCE · RUST · MIT LICENSE · ALPHA

The open source EDR in Rust that shows what it detects — and what it can't see yet.

Sentinelle is an EDR (Endpoint Detection & Response) written in Rust: an ETW sensor on Windows, a cross-platform sensor on Linux and macOS, 51 Sigma-style detection rules, process-tree correlation and a real-time SOC console. 100% self-hosted: no telemetry is ever sent to a vendor.

Act II · The mechanics

03 / 14HOW IT WORKS

How an EDR works: one event's journey through Sentinelle

We follow a single event — the PowerShell launch from the demo — all the way from the sensor to the console.

  1. 01 · SENSOR

    The sensor sees the process spawn

    On Windows, Sentinelle listens to ETW (the Microsoft-Windows-Kernel-Process provider, administrator rights required) and automatically falls back to polling if ETW fails to start. On Linux and macOS, it polls the process table roughly once per second. The NT path is resolved to a DOS path, the command line is enriched, and the PE's original name (OriginalFilename) is read.

    live: ETW Kernel-Process → process_start
here: captures/demo.jsonl, line 3 → process_start · C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe

  2. 02 · NORMALIZED EVENT

    One format for everything

    A flat, ECS/OCSF-style schema covering 7 event types: process, network, file, image load, process access, remote thread, named pipe.

    {"ts":"2026-10-05T20:00:02Z","host":"poste-test","kind":"process_start","pid":4200,"ppid":4100,"image":"C:\\Windows\\System32\\WindowsPowerShell\\v1.0\\powershell.exe","command_line":"powershell.exe -nop -w hidden -ep bypass -enc SQBFAFgA"}

  3. 03 · PROCESS TREE

    Who launched whom

    Sentinelle rebuilds the ancestry, so a rule can require that an ancestor is Office — not just the direct parent.

    powershell.exe ← winword.exe ← explorer.exe

  4. 04 · RULE ENGINE

    Sigma-style rules

    Operators equals, contains, starts_with, ends_with, regex and cidr; an and/or/not boolean tree; lineage matching; Sigma YAML rule import.

    → SNT-0001 · SNT-0010 · SNT-0012

  5. 05 · BEHAVIOR + YARA-X

    What a single rule can't see

    Four stateful detectors: process bursts (B001), mass file encryption (B002), parent process spoofing (B003), renamed binaries (B004). B002 and B003 are simulation-only: no live sensor supplies file writes or the real parent yet. Plus a YARA-X scan of process images.

    in this replay: B003 and B004 fire later (steps 5 and 6)

  6. 06 · SCORING

    Risk that rises and decays

    Per-host risk that accumulates and decays over time, weighted by each rule's confidence; an allowlist against false positives; deduplication.

    100 + 70 + 40 = 210

  7. 07 · CORRELATION

    From alerts to an incident

    Alerts from the same sequence (same host, 120-second window) form one incident: kill-chain progression, highest severity, cumulative score.

    poste-test · 120 s → 1 incident

  8. 08 · CONSOLE, RESPONSE, EXPORTS

    The analyst sees, decides, acts

    A real-time SOC console (SSE) built into the binary; process termination (Win32 TerminateProcess), locally and remotely; Markdown report (/api/report) and ATT&CK Navigator layer (/api/navigator).

    GET /api/stream · GET /api/report · GET /api/navigator

06 / 14FEATURES

Everything it does

RUL

Sigma-style rule engine and Sigma YAML import

Modifiers base64, windash, cidr, all; quantifiers “1 of” and “all of”.

CommandLine|base64|contains:
  - 'IEX'

TREE

Process tree and ancestry

Every process is linked to its ancestors, so a rule can target the entire lineage.

BEH

4 behavioral detectors

  • B001 burst of process creations
  • B002 mass file encryption simulation-only
  • B003 parent process spoofing simulation-only
  • B004 renamed sensitive binary (PE OriginalFilename)

YRX

YARA-X scanning

Scans process images with your own YARA rules.

SCR

Scoring

Per host × confidence, allowlist, deduplication.

INC

Incident correlation

Same host, 120-second window.

SOC

Real-time SOC console (SSE) built into the binary

Filters, search, severities, ATT&CK coverage, ancestry trail, host liveness.

RSP

Response

Win32 process termination, local and remote. Routes can be guarded by the SENTINELLE_TOKEN token: off by default, set it before any exposure (constant-time comparison for equal-length tokens).

EXP

Exports

Markdown report, ATT&CK Navigator JSON layer, incidents as JSON.

DB

SQLite persistence

Optional, with bounded retention and purging.

OBS

Observability

/api/health: events received and dropped, uptime, hosts.

Stack: Rust · tokio · axum · tonic · rustls · rcgen · ferrisetw · sysinfo · YARA-X · rusqlite · serde

07 / 14CROSS-PLATFORM

Windows, Linux, macOS: a sensor built for each system

WIN · ETW

Windows

illustration · stream pushed by the kernel

ETW Kernel-Process sensor (Administrator terminal), with polling as a fallback; 39 rules. Validated on a real Windows 11 Pro machine: live kernel ETW, SNT-0012, SNT-B001 and SNT-B004 detections on real processes, real Win32 kill. Defender may quarantine the unsigned binaries.

LINUX · POLLING

Linux

illustration · roughly one sample per second

Process-table polling (sysinfo, roughly every second); 12 Linux/macOS rules. Ubuntu CI on every commit; a realistic Linux attack chain from the test corpus is detected.

  • SNT-1000 curl|bash
  • SNT-1001 base64 → shell
  • SNT-1002 reverse shell /dev/tcp & nc -e
  • SNT-1003 chmod +x in /tmp
  • SNT-1004 execution from /tmp
  • SNT-1005 reading /etc/shadow & SSH keys
  • SNT-1006 cron persistence
  • SNT-1007 .bashrc/.zshrc persistence
  • SNT-1008 shell history clearing

Polling can miss very short-lived processes.

MACOS · POLLING

macOS

illustration · same sensor as Linux

Same sensor; rules SNT-1009 (osascript “do shell script”), SNT-1010 (SIP/Gatekeeper disabled), SNT-1011 (LaunchAgent/LaunchDaemon). Validated live: a real SNT-1002 detection, plus one false positive found under real conditions and then fixed.

08 / 14ARCHITECTURE

Self-hosted EDR: one endpoint or a whole fleet, over gRPC + mTLS

MODE 1 · SINGLE ENDPOINT

sentinelle-agentd, with the console built in at http://localhost:8787.

MODE 2 · FLEET

Agents ↔ central server over gRPC with mutual TLS (tonic + rustls). The PKI is generated in pure Rust by sentinelle-certgen (rcgen, no openssl). Kill orders are pushed to the agents. Heartbeats drive host liveness: live, lagging or silent.

No kernel anti-tamper: an administrator can stop the agent.

Workspace · 10 crates

  • common pure core: events, rules, scoring, correlation
  • sensor-windows ETW sensor
  • sensor-proc cross-platform polling sensor
  • scan YARA-X scanning

  • proto gRPC definitions

10 / 14REAL COVERAGE

Real coverage: what Sentinelle can't see yet

45/ 51

rules fed by a live sensor

live simulation-only

45 of the 51 rules rely on a live sensor. The other 6 exist, but are still waiting for their sensor source (Sysmon / additional ETW providers).

  • SNT-0100 network
  • SNT-0101 file write
  • SNT-0200 image or driver load
  • SNT-0300 LSASS handle access
  • SNT-0310 remote thread
  • SNT-0320 named pipe

In the replay, SNT-0300, SNT-0320 and SNT-B003 fire because the scenario supplies those fields. In live mode, they still lack a sensor.

On top of that, 2 behavioral detectors have no live source: SNT-B002 (file writes) and SNT-B003 (real parent, real_ppid). /api/coverage/reality only lists rules, so it does not mention them.

curl http://localhost:8787/api/coverage/reality

A blind spot you can see is a blind spot you can fix.

14 / 14FAQ

Sentinelle EDR: frequently asked questions

What is an open source EDR?

An EDR (Endpoint Detection & Response) monitors activity on endpoints (processes and more), detects malicious behavior and lets you respond to it. Sentinelle is open source under the MIT license: its code and its 51 rules are readable and auditable.

Does Sentinelle replace CrowdStrike, SentinelOne or Microsoft Defender for Endpoint?

No. Sentinelle has no kernel anti-tamper, no large-scale threat intelligence and no 24/7 SOC. It is meant for learning, auditing, self-hosting or complementing an existing setup.

Is Sentinelle self-hosted? Does it send data to a vendor?

Yes, it is fully self-hosted: no telemetry is sent to any vendor.

Which operating systems are supported?

Windows (ETW sensor, with polling as a fallback), Linux and macOS (process-table polling, roughly every second). 39 Windows rules and 12 Linux/macOS rules.

Is it compatible with Sigma rules?

Yes: it imports Sigma YAML rules with the base64, windash, cidr and all modifiers, and the “1 of” and “all of” quantifiers.

How is MITRE ATT&CK coverage measured?

Each rule declares its ATT&CK techniques: 51 distinct techniques and sub-techniques (37 base techniques), 10 tactics covered. Initial Access is not covered. The console exports an ATT&CK Navigator layer (/api/navigator).

What does “simulation-only” mean?

6 rules (network, file write, image load, LSASS handle access, remote thread, named pipe) exist but don't have a live sensor yet. They fire during replay. The /api/coverage/reality endpoint reports this. The SNT-B002 (file writes) and SNT-B003 (real parent) behavioral detectors have no live source either; that endpoint does not mention them.

Why does Windows Defender quarantine Sentinelle?

The binaries are not signed (Authenticode). That is expected for an unsigned EDR: exclude the folder in Windows Security.

Does it need administrator rights?

On Windows, yes, for the ETW sensor. Without them, Sentinelle automatically falls back to polling.

Can I use it in production?

Sentinelle is alpha software maintained by a single person. Read the known limitations before any deployment.

How do I add a rule?

Add a JSON entry to crates/common/rules.json and rebuild (native rules are compiled into the binary), or drop a Sigma YAML file into a folder set via SENTINELLE_RULES_DIR (for example ./rules.d). An allowlist helps reduce false positives.
